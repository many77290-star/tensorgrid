The problem

You don't have a data problem. You have a plumbing problem.

Every team working on Bittensor — stakers, subnet operations, market makers, quant desks — rebuilds the same pipeline from scratch to answer one simple question: which subnet alpha actually beats TAO, and is it liquid enough to trade?

Without TensorGrid

  • ✕ Paid API keys to get pool data, no self-hosted alternative
  • ✕ Raw CoinGecko feed: prices only, no market cap rank, no liquidity view
  • ✕ CoinGecko glitches: +5,000% fake 30d moves polluting your signals
  • ✕ An on-chain btcli chain to read subnet details when you need more
  • ✕ A private script each teammate writes, none shared, none maintained

With TensorGrid

  • → One normalized dataset: price, market cap, volume, 24h/7d/30d, rank
  • → Glitch-filtered 30d performance — anomalies neutralized and flagged
  • → The decision metric, pre-computed: alpha vs TAO, 30d, per token and across the universe
  • → Daily historical snapshots on top, ready for backtests and alerts
  • → One JSON endpoint to integrate, one terminal to read — no per-employee pipeline
